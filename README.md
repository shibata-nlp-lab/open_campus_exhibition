# オープンキャンパス LLM 展示アプリ

高校生向けに「LLM は次の単語の確率を予測しているだけ」を体験してもらうデスクトップ展示アプリ。
Electron + React + TypeScript。設定画面でシナリオを組み、全画面の進行画面で来場者に見せます。

このファイルは**使う人向け**です。コードをさわる場合は [docs/](docs/) を参照してください
（[アーキテクチャ](docs/architecture.md) / [IPC](docs/ipc.md) / [データとスキーマ](docs/data.md) /
[コンテンツ種別](docs/content-types.md) / [トークナイザと埋め込み](docs/nlp.md) / [開発ガイド](docs/development.md)）。

## 使い方

```bash
npm install
```

開発（ホットリロード付き）:

```bash
npm run dev
```

ビルドして起動:

```bash
npm start
```

配布用パッケージ:

```bash
npm run dist:mac
```

詳細は「[配布ファイルの作り方](#配布ファイルの作り方)」を参照。

## 配布ファイルの作り方

electron-builder で作ります。成果物は `release/` に出ます。

| コマンド | 作られるもの |
| --- | --- |
| `npm run dist:mac` | `LLM Exhibit-<版>-mac-arm64.dmg` / `.zip`（Apple Silicon 用） |
| `npm run dist:win` | `LLM Exhibit-<版>-win-x64.exe`（NSIS インストーラ。Windows 上で実行） |

macOS 版は Windows 上では、Windows 版は macOS 上では作れません（ネイティブモジュールと署名のため）。
両方まとめて作りたいときは、後述の GitHub Actions に任せるのが確実です。

手元でビルドするときの注意:

- **iCloud Drive 同期下（`~/Documents` など）では失敗します。** `node_modules` の読み出しが同期待ちになり、
  `ETIMEDOUT: connection timed out, read` で落ちます。同期外（例 `~/dev/open_campus`）で実行してください
- **arm64 の Node を使ってください。** Rosetta の x64 Node で `npm ci` すると sharp の x64 版が入り、
  arm64 アプリに x64 バイナリが同梱されます（WASM 版へのフォールバックで動きはしますが遅くなります）。
  `node -p process.arch` が `x64` を返す場合は arm64 版の Node に入れ替えるか、GitHub Actions でビルドしてください
- できあがるアプリは 600MB 前後（dmg で 210MB 前後）です。onnxruntime の共有ライブラリと Electron 本体が大半を占めます

### GitHub Actions（CI）

| ワークフロー | いつ動くか | すること |
| --- | --- | --- |
| `.github/workflows/ci.yml` | main への push / Pull Request | 型チェックとビルドが通るかだけ確認（1〜2分） |
| `.github/workflows/release.yml` | `v` で始まるタグの push、または手動実行 | macOS(arm64) と Windows(x64) を並列ビルドし、タグのときは GitHub Release に添付 |

リリース手順:

```bash
npm version patch   # package.json の版を上げてタグを打つ
git push --follow-tags
```

10〜15分ほどで Releases に dmg / zip / exe が並びます。
版を上げずに動作だけ試したいときは、GitHub の Actions タブから Release ワークフローを手動実行すると、
Release は作らずに成果物（Artifacts）だけが残ります。

### 受け取った人がやること（macOS）

Apple Developer ID を持っていないため、配布物には**アドホック署名しか付いていません**（`scripts/adhoc-sign.mjs`）。
そのため初回起動時に「開発元を確認できないため開けません」と出ます。次のどちらかで開きます。

- アプリを **右クリック →「開く」**（初回だけ。2回目以降は普通に起動できる）
- それでも駄目なら、ターミナルで検疫属性を外す:

```bash
xattr -cr "/Applications/LLM Exhibit.app"
```

Developer ID を用意できる場合は、証明書(.p12)とパスワードを GitHub Secrets（`CSC_LINK` / `CSC_KEY_PASSWORD`）に登録し、
`release.yml` の `CSC_IDENTITY_AUTO_DISCOVERY: 'false'` を外せば、そのまま署名付きビルドになります。

## macOS で「マルウェアがブロックされました」と出るとき

npm の Electron バイナリはアドホック署名しか持たないため、次の2つで Gatekeeper に弾かれることがあります。

1. 古い Electron の notarization が Apple 側で失効している（`spctl -a -t exec node_modules/electron/dist/Electron.app` が `revoked` を返す）→ **Electron を最新に上げる**
2. プロジェクトが iCloud Drive 同期下（`~/Documents` など）にあり、同期で `Electron.app` の署名リソースが壊れる → **署名し直す**

`npm install` 時に `scripts/fix-macos-electron.mjs` が自動で署名し直します。手動で実行する場合:

```bash
npm run fix-electron
```

再発する場合は、プロジェクトを iCloud 同期外（例 `~/dev/open_campus`）に移すのが確実です。

## 画面構成

- **設定画面**（起動時に開く）
  - シナリオ … コンテンツを並べ替えて展示の流れを作る。複数作成・切り替え可。「▶ このシナリオで開始」で進行画面が開く
  - コンテンツ … 8 種類の部品を作成・編集
  - 全般 … 展示タイトル、全画面、モニター構成、キーボード操作一覧、サンプル教材の読み込み
  - API … OpenAI API キー（OS キーチェーンで暗号化保存）、モデル、接続テスト
  - 集計結果 … クイズ / ゲーム / アンケートのログ表示・CSV 書き出し
- **進行画面**（全画面）… シナリオを順に再生。外部モニターがあればそちらに全画面表示
- **コントローラ画面**（本体画面）… 進行画面を外部モニターに出したときだけ自動で開く。現在／次のコンテンツ、**進行メモ**、経過時間、シナリオ一覧（クリックでジャンプ）、前後移動、待機画面の切替、モニター切替、終了

進行メモ（コンテンツごとに設定できる台本用の覚え書き）とキーボード操作の一覧は
**コントローラ画面にだけ表示され、来場者側の進行画面には出ません**。
来場者側に残るのは展示タイトル・進捗ドット・ページ番号・前後ボタンだけです。
モニター1台構成ではコントローラが開かないため、メモとキー一覧はどこにも表示されません。

### マルチモニター運用

「全般」タブの2つのトグルで制御します（既定は両方オン）。

- 外部モニターがあれば、そちらに進行画面を全画面表示する
- そのとき本体画面にコントローラを表示する

モニターが1台のみならこれまでどおり本体画面に全画面表示され、コントローラは開きません。
本番中にモニターを抜き差ししても一覧は自動更新され、コントローラのモニターボタンから進行画面を移動できます。
コントローラを閉じると進行画面も終了します（逆も同様）。

### キーボード操作

**進行画面・コントローラ画面のどちらがアクティブでも同じキーが効きます**。
一覧はコントローラ画面に表示されます（来場者側の進行画面には出しません。「全般」タブで非表示にもできます）。

コントローラ側で押した `→` / `←` は進行画面へ転送され、スライドのページ送りなどコンテンツ内部の移動として扱われます。
`F` はコントローラからでも「進行画面」の全画面を切り替えます。

| キー | 動作 |
| --- | --- |
| → / Space | 次へ（スライド送り等） |
| ← | 戻る |
| N / P | 次 / 前のコンテンツ |
| S | 待機画面の表示 / 解除 |
| M | 音声の停止 / 再開（BGM・ナレーション・動画をまとめて） |
| A | 自動モードの入り / 切り |
| R | 最初から |
| F | 全画面切替 |
| Esc | 進行画面を閉じる |

設定画面の「シナリオ」タブには **「⏩ 自動モードで開始」** があります。音声を流し、設定した
待ち時間で自動的に次の画面へ進む、人が付かない展示用のモードです（[自動モード](#自動モード)）。

同じタブの **「🔇 音声を止めて開始」** は下見用です。隣で別の説明をしているときや、
夜に自宅で流れを確認したいときの下見用です。止めている間は進行画面とコントローラに
その旨を出します（音が出ないのを不具合と勘違いしないため）。`M` でいつでも戻せます。

## コンテンツ種別

| 種別 | 内容 | API |
| --- | --- | --- |
| 動画 | mp4/webm 再生。音声 on/off は設定でも再生中でも切替可。終了で自動送り | 不要 |
| スライド | Markdown / Marp（`---` で改ページ。アプリ内編集 or ローカル .md 参照）/ PDF（pdf.js でページ送り）/ HTML。音声を重ねられる | 不要 |
| クイズ | 設定画面で問題・選択肢・正解・解説を作成。制限時間、音声あり | 不要 |
| インタラクティブ1 | 入力文をトークナイズ → 埋め込みベクトル化 → ヒートマップと PCA 2D で可視化。分割は GPT-4o / llm-jp / Ruri v3、ベクトル化は OpenAI / ローカル Ruri v3 から選択 | Embeddings（ローカル Ruri を選べば不要） |
| インタラクティブ2 | 入力文の続きを 1 トークンずつ予測。`top_logprobs` の候補と確率を表示し、来場者が選べる | Chat Completions |
| ゲーム | 次の単語当ての選択式クイズ。問題・候補・確率は事前作成 | 不要 |
| アンケート | ＋/− で人数を変えつつ、選択肢ごとに人数を計上。5 段階評価にも対応。音声あり | 不要 |
| 待機画面 | 説明の合間の「お待ちください」画面。BGM・時計・カウントダウン付き | 不要 |

### Marp との連携

スライドの「Markdown の取得元」で **ローカルの .md ファイルを指定する** を選ぶと、
ファイルをコピーせず元の絶対パスを参照します。

- Marp（VS Code 拡張など）で編集した内容は、進行画面を開き直すだけで反映されます
- 画像の相対パスは .md のあるディレクトリ基準で解決されます（`ocfile://` プロトコル経由で読み込み）

### `marp: true` を書くと本家の Marp で描画します

フロントマターに `marp: true` があるスライドは、**Marp 本体（Marp Core）がそのまま描画**します。
テーマ・ディレクティブ・レイアウトは Marp for VS Code のプレビューと同じ結果になります。

```markdown
---
marp: true
paginate: true
theme: gaia
style: |
  section.title h1 { text-align: center; }
---
<!-- _class: title -->
# ご覧いただきありがとうございました
```

- **テーマは `default` / `gaia` / `uncover` が最初から使えます**
- **自作テーマも使えます。**「全般」タブの **Marp の自作テーマ（CSS）** に、
  `/* @theme 名前 */` で始まる CSS ファイルを登録すると `theme: 名前` で指定できます。
  ファイルは参照するだけなので、編集すればスライドを開き直したときに反映されます
- 外部フォントの読み込み（`@import "https://…"`）は取り除きます。**会場に回線が無くても待たされません。**
  そのぶんテーマ本来の書体ではなく、PC にある書体で表示されます

**`marp: true` が無い Markdown はこれまでどおりの簡易描画です。** 同梱の教材はこちらなので、
見た目は変わりません。簡易描画でも `---` での改ページ、`style:`、`<!-- _class: … -->`、
`paginate` には対応しています（`theme:` は当たりません）。

## 最初から入っている教材

初回起動時に、高校生向けの教材一式が入った状態になります（`src/content/samples.ts`）。

**スライド 7 本（計 38 ページ）**

1. イントロ：AIはどうやって文章を作る？（よくある勘違い → 正体は次の語の予測）
2. ことばを数字にする（トークン → ID → 埋め込みベクトル）
3. 文脈を読む仕組み（「はし」の例からアテンションへ）
4. 次の1語を選ぶ（確率の表・温度・毎回答えが変わる理由）
5. 学習ってなにをしているの？（穴埋め練習・パラメータ・人による調整）
6. AIが苦手なこと（ハルシネーションがなぜ起きるか）
7. これからどう付き合う？（使い方のコツ・大学の学問とのつながり）

**クイズ 2 本（基礎 4 問／発展 4 問）・ゲーム 6 問・アンケート 3 設問**

ゲームには「川にかかった**はし**を ___」「手を洗ってから**はし**を ___」のように、
同じ語でも文脈で確率がまるごと変わることを体感できる問題を入れてあります。

**シナリオ 2 本**

- フル版（約25分）… 説明を一通り。体験②→ゲーム→発展クイズまで
- ショート版（約12分）… 来場者の回転が速いとき用。体験とゲーム中心

### 既存の config への反映

同梱教材には版番号（`SAMPLES_VERSION`）が付いており、起動時に自動で取り込まれます。

- **初期サンプルのまま何も編集していない config** … 重複を避けるため教材一式を新しいものに入れ替え
- **自分で作ったコンテンツやシナリオがある config** … 足りない教材だけを追加（既存のものは一切削除・上書きしません）

判定は `sampleId` と名前・中身の照合で行うため、一度編集したり削除したりしたものが復活することはありません。
手動で取り込み直したいときは「全般」タブの **サンプル教材を追加読み込み** を押してください。

教材を更新したときは `src/defaults.ts` の `SAMPLES_VERSION` を上げると、既存環境にも配られます。

## 自動モード

**人が付かなくても回り続ける**モードです。設定画面「シナリオ」タブの **「⏩ 自動モードで開始」** から入ります。

各画面で**音声を鳴らし、鳴り終わってから設定した秒数だけ置いて、次の画面へ**進みます。
音声が無い画面は「画面が出てから」その秒数で進みます。待ち時間はコンテンツごとに設定でき、
体験①②は**画面ごと**に持てます（音声と同じ欄に並んでいます）。

来場者の入力が要る画面は、**設定画面で先に決めておきます**。

| コンテンツ | 事前に決めること |
| --- | --- |
| 体験① | 入力する文 ／ ベクトル画面で順に見せる単語（`1, 3, 5` のように複数。1つごとに待ち時間ぶん止まります） |
| 体験② | 入力する文 ／ 何番目の候補を選ぶか ／ 何語ぶん選ぶか |

体験②では、**1語選んだあとの画面に別の音声**を当てられます（「最初の候補が出た画面」と
「1語選んだあとの画面」で説明を変えられます）。

体験①の**ベクトル画面でフォーカスを移すところだけは、音声の終わりを待ちません**。
1本のナレーションで複数の単語を順に説明する使い方を想定しているためで、指定した秒数ごとに
次の単語へ移ります（最後の単語まで見せたあと、音声が終わるのを待って次のコンテンツへ進みます）。

クイズ・ゲーム・アンケートは答える人がいないので、待ち時間ぶん見せて次へ進みます。

**自動モード中は、コントローラの進行操作を受け付けません**（前へ・次へ・最初から・待機画面・
シナリオ切替・ステップの直接移動）。キーボードの `N` `P` `S` `R` `←` `→` も同じく止まります。
うっかり触って自動送りと二重に進むのを防ぐためで、コントローラの
**「⏹ 自動モードを解除して手動に戻す」**（または `A`）でいつでも手動に戻せます。

**分岐（体験に戻る）に来たとき**の動きは 2 通りです。

- 誰かが「体験する」を押した → **自動モードを解除**します（人が操作を引き取ったとみなす）
- 誰も押さないまま待ち時間が過ぎた → **待機画面**へ移ります（次の説明を無人で始めない）

進行画面とコントローラには自動モード中である旨を出します。`A` キーでいつでも入り／切りできます。

## ポン出し

コントローラのボタンで、**進行中の音に重ねて**音を鳴らせます。拍手・ジングル・効果音など、
進行を止めずに足したいものに使います。設定画面の **「ポン出し」** タブで並べておくと、
コントローラにボタンが出ます。

- 鳴らせるのは**同時に1つ**です（次を押すと前の音は止まります）
- **ループ**にしておくと、もう一度押すまで鳴り続けます（開始前の BGM など）
- `M` で音声をまとめて止めている間は、ポン出しも鳴りません

## 待機モード

説明の合間に「お待ちください」を出す仕組みです。使い方は2通り。

- **シナリオに挟む** … 待機画面コンテンツをステップとして配置。自動で次へ進む秒数を設定するとカウントダウン表示になります
- **いつでも重ねる** … 進行中に `S` キー、またはコントローラの「待機画面を表示」ボタン。現在のコンテンツの上にかぶせて表示し、解除するとその続きから再開します

BGM は待機画面ごとに設定でき、表示している間だけ鳴ります（進行画面で 🔊 ボタンによる切替も可能）。
オーバーレイで出すときは、シナリオ内の待機画面コンテンツの設定（BGM 含む）が使われます。

## データの保存先

`app.getPath('userData')`（macOS なら `~/Library/Application Support/open-campus-llm-exhibit/`）

- `config.json` … シナリオ・コンテンツ・設定
- `assets/` … 取り込んだ動画・PDF・画像・音声（スライド本文は config.json 内に保存）
- `openai.key` … API キー（safeStorage で暗号化）
- `results.jsonl` … クイズ / ゲーム / アンケートのログ

アセットは `oc://assets/<ファイル名>` というカスタムプロトコルで参照します。

## 当日運用のヒント

- ネットワーク断に備え、インタラクティブ1/2 は API 失敗時にオフライン用の疑似計算へ自動フォールバックします（画面に明示されます）。ゲーム・クイズは完全オフラインで動きます。
- グループの入れ替え時は `S` キー（またはコントローラの待機ボタン）で待機画面を出しておくと、来場者を待たせている状態が伝わります。
