# ユーザーと権限

展示員ごとにユーザーを作り、触れる範囲を分ける仕組みです。

> **これはセキュリティ機構ではありません。**
> config.json も users.json も同じPCの中にあり、ファイルを直接編集すれば誰でも変えられます。
> 目的は「当日に展示員が設定を触って壊す」「APIキーを見てしまう」といった**事故を防ぐ仕切り**です。
> 本当に守りたいものがあるなら、OS のアカウント分離やディスク暗号化を併用してください。

## 役割

| 役割 | 設定画面 | ユーザー管理 |
| --- | --- | --- |
| **オーナー** | すべて | 誰でも変更・削除できる |
| **アドミニストレーター** | API 以外 | エディター / ユーザーのみ |
| **エディター** | シナリオ・コンテンツのみ | 不可 |
| **ユーザー** | 開けない（シナリオの実行だけ） | 不可 |

対応表は [src/permissions.ts](../src/permissions.ts) の `TAB_ALLOW` が正です。
main と renderer の両方から同じ表を参照しています。

`ユーザー` でログインすると設定画面の代わりに**シナリオを選んで開始するだけの画面**が出ます。

始め方は設定画面と同じ4つ（**通常 / 自動 / 音声なし / 待機画面**）から選べます。
当日の状況（隣で別の説明をしている、人手が足りない）で変えたくなるものなので、
編集の権限がなくても選べるようにしてあります。文言と組み合わせは
[src/playModes.ts](../src/playModes.ts) にまとめてあり、設定画面のシナリオタブと共通です。

## 初期状態と詰まないための規則

ユーザーが1人も登録されていなければ**認証そのものを使いません**（これまでどおり誰でも触れます）。
「ユーザー」タブで最初の1人を作った時点から、ログインが必要になります。

事故で誰も管理できなくなるのを防ぐため、次の規則を入れてあります。

- **1人目は指定に関わらずオーナーになる**
- **1人目を作った本人は、そのままログイン状態になる**（自分で締め出されない）
- **自分自身の権限は変更できない**
- **最後のオーナーは降格も削除もできない**
- アドミニストレーターは**自分より上位を作れない・操作できない**

## PIN の扱い

- 4〜8桁の数字。展示中に素早く入れられることを優先しています
- **生の PIN は保存しません。** ユーザーごとのランダムなソルトで scrypt にかけ、ハッシュだけを
  `userData/users.json` に置きます
- **ハッシュはレンダラに渡しません。** `auth.list()` が返すのは `id` / `name` / `role` だけです
- 照合は `timingSafeEqual` を使います。存在しない ID でも同じ文言を返し、どの ID があるかを探れないようにしています

### 全員分の PIN を忘れたとき

`userData/users.json` を削除すると、認証なしの初期状態に戻ります
（設定画面の「ユーザー」タブに、場所を開くボタンがあります）。
これは回避策であると同時に、冒頭のとおり**これがセキュリティ機構ではない**ということでもあります。

## 実装

| 場所 | 役割 |
| --- | --- |
| [src/permissions.ts](../src/permissions.ts) | 対応表と判定。純粋関数なのでテストしやすい |
| [electron/users.ts](../electron/users.ts) | users.json の読み書き、scrypt、セッション |
| [src/settings/LoginScreen.tsx](../src/settings/LoginScreen.tsx) | ログイン |
| [src/settings/UsersPanel.tsx](../src/settings/UsersPanel.tsx) | ユーザーの追加・権限変更・PIN再設定 |
| [src/settings/SettingsApp.tsx](../src/settings/SettingsApp.tsx) | タブの出し分けとランチャー画面 |

セッション（誰がログインしているか）は**メインプロセスだけが持ちます**。
レンダラは `auth.state()` で聞くだけです。

**画面を隠すだけでは足りない操作は、メイン側でも確認します。** 現在そうしているのは
APIキーの設定（`key:set`）で、`canOpenTab(role, 'api')` を通らなければ弾きます。
権限が要る操作を足すときは、同じようにハンドラ側でも見てください。

テストは [test/permissions.test.ts](../test/permissions.test.ts)（対応表）と
[test/users.test.ts](../test/users.test.ts)（保存・ログイン・昇降格の規則）にあります。
